# ゴール4：結合とデプロイ準備

server/・web/・device/ を結合し、ローカルで「端末 → サーバー → スマホ」の押印フローが通ることを確認する。

## 完了条件

E2E テストが全て通ること。

- server/ から web/ のビルド成果物を配信し、同一オリジンで動く
- device/ に、カメラを使わずトークンを送る模擬端末モードを追加する
- 模擬端末で押印すると、Playwright で開いた web/ のスタンプ帳に反映される
- サーバー停止中に押印すると一時保存され、サーバー再起動後に再送されて web/ に反映される
- 16:00までに一時保存した押印は10月31日中の再送で反映され、11月1日以降は反映されず端末キューが空になる
- 5スポット分押印するとゴールページに遷移する
- web/ をビルドして server/ から配信する単一の Dockerfile を用意する
- docs/deploy.md にデプロイ手順書を書く。次を含める
  - 12-2 の Cloud Run 設定（リハーサル日とイベント前日〜当日のみ min-instances 1 と CPU 常時割り当て、それ以外は 0）
  - Supabase の Session mode プーラー接続文字列の設定と、RLS の確認方法
  - /api/health を3日おきに呼ぶ Cloud Scheduler の設定（Supabase の一時停止防止）
  - 当日の朝と前日に確認すること
