# `design.md` 修正事項 — 見開き型スタンプ帳

この文書は、参加者向けの電子スタンプ帳を、円形のすごろくマップから「開いた紙のスタンプ帳」へ変更するための修正事項をまとめたものである。`docs/design.md` 本体は変更せず、反映時の差分仕様として扱う。

## 1. 変更の目的

- 画面を見た瞬間に「スタンプ帳へスタンプを押して集める体験」だと伝わるようにする
- 円形の道、地面、木による「すごろくマップ」の印象をスタンプ帳画面から取り除く
- 見開きの左ページに2枠、右ページに3枠を配置し、紙面へ直接押印しているように見せる
- スマートフォンでは、影、紙の重なり、GOALしおりまで含めて画面内へ収め、見切れと横スクロールを発生させない
- QR表示を独立したカードに見せず、スタンプ帳の押印欄を拡大した紙面として見せる
- スタンプ帳画面では「スタンプラリー」の画面タイトルと「0/5」形式の進捗カウンターを表示せず、見開きそのものを主役にする
- 回る順番は自由という仕様（spec Q-13）を、矢印や接続線を置かないことと案内文で伝える

## 2. `design.md` 0章「方向性」の修正

冒頭の方向性を次の内容へ差し替える。

- **レイアウト**は、中央に綴じ目がある見開きのスタンプ帳とする
- 左ページに2つ、右ページに3つ、合計5つの正方形の押印欄を置く
- 5つの押印欄は同じ大きさとし、左ページの2枠は上下方向の中央に均等配置する
- 押印欄同士を道、線、矢印で結ばない。番号はスポットの識別にだけ使い、訪問順を表さない
- 紙、綴じ目、ページの重なり、しおりで「開いた本」を表現する
- ネオブルータリズムの配色、太い枠線、ぼかしのない影、太い丸ゴシックは維持する
- スタンプ帳画面では、緑の地面、黄土色の道、木の装飾を使わない

「ゴールページはスタンプ帳の中央のGOALから開く」は、次の内容へ変更する。

- **ゴールページ**は、見開き下部中央のGOALしおりから開く（完走後）。5個目の押印時は従来どおり自動で遷移する

画面遷移図の `book -- 完走後のGOAL --> goal` は意味を維持し、GOALの表示位置だけを中央のメダリオンから下部のしおりへ変更する。

## 3. デザイントークンの修正

既存の色を使用し、見開き専用の新しい色は追加しない。紙面には `--color-surface`、画面背景には `--color-bg`、綴じ目と輪郭には `--color-ink` を使う。

空欄の押印欄に使う破線をトークンとして追加する。

```css
--border-stamp-slot: 3px dashed var(--color-muted);
```

`--color-board`、`--color-road`、`--color-tree` はスタンプ帳画面では使わない。ゴールページやマップなど、既存の別画面で必要な間は削除しない。

## 4. コンポーネントの修正

### 4-1. OpenStampBookを追加

見開き全体を表すコンポーネントを追加する。

- 外側に `OpenStampBookFrame` を置き、影、背面の紙、GOALしおりを含む表示領域を管理する
- `OpenStampBookFrame` の幅は `min(100%, 360px)` とし、`box-sizing: border-box` を使う
- 見開き本体の横幅は、右側の `--shadow-lg` と紙のずれを差し引いた値にする。装飾を含む外接矩形が `OpenStampBookFrame` からはみ出してはならない
- 見開き本体の縦横比はおおむね `1.1 / 1` とする。ただし、押印欄の最小寸法を保つために必要な場合は高さを内容に合わせて広げる
- 背景は `--color-surface`、外枠は `--border`、外側の影は `--shadow-lg`
- 外周の角丸は `--radius-card`
- 中央を左右に二等分し、中央の綴じ目を `--border-thin` で表す
- ページの外側に、背面の紙が4pxずれて重なって見える装飾を置く。ずれはフレームの内側へ向け、装飾は操作対象にせず `aria-hidden="true"` とする
- 綴じ目や紙の重なりに、グラデーション、ぼかし、半透明を使わない
- GOALしおりの表示領域をフレームの高さへ含め、後続コンテンツと重ならない余白を確保する
- ページ全体で `overflow-x: hidden` を使って見切れを隠すのではなく、装飾を含む寸法そのものを画面内へ収める

### 4-2. BookStampSlotを追加

スタンプ帳内だけで使う正方形の押印欄を追加する。マップで使う円形の `SpotMarker` / `StampSlot` とは分ける。

共通:

- 5枠すべて同じ大きさとし、一辺は `clamp(72px, 22vw, 88px)` を目安とする
- 正方形、背景 `--color-surface`、角丸 `--radius-button`
- 左上にスポット番号を示す小さな紫のバッジを置く。番号は訪問順ではなく識別番号である
- DOM順とフォーカス順はスポット1〜5のデータ順とする
- 日本語・英語ともに、アクセシブルネームへスポット名と状態を含める

未押印:

- `<button>` とし、タップすると従来どおり全画面のQR表示を開く
- 枠線は `--border-stamp-slot`、影は `--shadow-sm`
- 中央にstampアイコンと「ここに押す」（英語は「STAMP HERE」）を配置する
- 最小タップ領域は72×72pxを確保する
- 押下時は影の分だけ沈み、`focus-visible` は既存の共通ルールに従う

押印済み:

- 操作できない要素とし、影を付けない
- 外枠は `--border-stamp-slot` のまま残し、紙面の押印位置であることを示す
- `StampImage` を枠の85〜90%で重ね、スポットごとの既存の傾きを維持する
- スタンプ画像は番号バッジより前面に出さず、隣の押印欄や綴じ目には重ねない

### 4-3. スタンプ帳画面からProgressBadgeを外す

- スタンプ帳画面には `ProgressBadge` / `ProgressSticker` を配置しない
- 「0/5」「2/5」「5/5」のような数値カウンターを表示しない
- 進捗は、5つの押印欄に表示されるスタンプ画像とGOALしおりの状態で伝える
- 読み上げ利用者には、見開き全体のアクセシブルネームまたは説明文で取得済みの数を伝えてよい。ただし画面上へ数値カウンターは追加しない

### 4-4. GoalMedallionをGoalBookmarkへ置き換える

- 見開きの下部中央から下へ出る、縦長のしおりとして表示する
- 幅112px以上、高さ52px以上とし、旗アイコンとGOALの文字を置く
- 未完走時は背景 `--color-ink`、文字 `--color-surface`。「あとNこ」または「5こでGOAL」を表示し、操作不可・影なしとする
- 完走後は背景 `--color-yellow`、文字 `--color-ink`、「COMPLETE」を表示し、`--shadow-md` を付けたボタンにする
- 完走後だけタップでゴールページを開く
- しおりは押印欄へ重ならず、画面横幅からはみ出さない

### 4-5. 既存コンポーネントの扱い

- `BoardCard` はスタンプ帳画面から外す。ゴールページの道の帯などで必要な場合は残す
- 円形の `SpotMarker` / `StampSlot` はマップ表示など、場所を示す用途に限定する
- `GoalMedallion` はスタンプ帳画面では使用せず、参照がなくなれば削除する
- `StampImage` の画像パス、代替画像、スポットごとの傾きは変更しない

## 5. `design.md` 4-1「電子スタンプ帳」の差し替え内容

共通ヘッダーの下に、上から次の順で配置する。

1. **案内文。** 「好きな順番で集めよう！」（英語は「Collect them in any order!」）を中央揃えで表示する
2. **OpenStampBook（見開き）。** 左ページにスポット1・2、右ページにスポット3・4・5のBookStampSlotを配置する
3. **操作の補足。** 「空いている押印欄をタップすると、機械に押し当てるQRが出ます。」（英語は「Tap an empty stamp space to show the QR for the stamp machine.」）を14px、中央揃えで表示する
4. **案内ボタン。** InfoTileを既存どおり3つ横並びにする

現在のタイトル行は削除する。縁取り見出し「スタンプラリー」（英語は「STAMP RALLY」）と、右側の `ProgressBadge` は表示しない。その分の余白も残さず、案内文から画面内容を始める。

見開き内の配置は次を基準とする。

```text
┌──────── 左ページ ────────┬──────── 右ページ ────────┐
│                          │  ┌────────┐              │
│  ┌────────┐              │  │  押印欄3  │              │
│  │  押印欄1  │              │  └────────┘              │
│  └────────┘              │  ┌────────┐              │
│                          │  │  押印欄4  │              │
│  ┌────────┐              │  └────────┘              │
│  │  押印欄2  │              │  ┌────────┐              │
│  └────────┘              │  │  押印欄5  │              │
│                          │  └────────┘              │
└──────────────────────────┴──────────────────────────┘
                         ▼ GOALしおり
```

- 左ページの2枠と右ページの3枠は同じ大きさにする
- 左ページは2枠を縦方向の中央へ均等配置する
- 右ページは3枠を上下均等に配置する
- 左右ページの内側余白は最低8px、押印欄同士の間隔は最低8pxとする
- 中央の綴じ目と押印欄の間にも最低8pxを確保する
- スポット番号は1から5まで表示するが、順番を示す矢印や道は置かない

## 6. QR表示を「押印欄の拡大」に見せる修正

QR表示は全画面のまま維持するが、独立した案内画面ではなく、見開きの押印欄へ近づいて紙面を拡大した状態としてデザインする。

### 6-1. 画面遷移

1. 未押印のBookStampSlotをタップする
2. タップした押印欄を起点に、見開き全体が画面中央へ拡大する
3. 周囲の押印欄と本の外周は画面外へ移動し、選択したページの紙面、綴じ目またはページ端の一部だけを残す
4. 押印欄が大きな正方形の押印エリアへ変化し、その中央にQRを表示する
5. 戻る操作では逆方向に縮小し、元の見開きへ戻る

タップした押印欄は拡大アニメーションの起点としてだけ扱う。QRトークンは従来どおり共通で、実際のスポットは押し当てた機械によって決まるため、拡大後にスポット名やスポット番号を表示しない。押印完了後はSSEで通知された正しいスポットの押印欄へスタンプを表示する。

### 6-2. 拡大後の紙面

- 背景全体を `--color-surface` の紙面とし、独立したCardが画面中央へ浮いている見た目をやめる
- 左ページの押印欄から開いた場合は画面右端寄りに綴じ目の一部、右ページから開いた場合は画面左端寄りに綴じ目の一部を見せる
- 綴じ目とページ端は装飾であり、操作要素にしない
- 上部にTag「ここで押印」（英語は「STAMP HERE」）と、見出し「機械を押し当てる」（英語は「PRESS THE STAMP MACHINE」）を置く
- 中央に一辺 `min(260px, calc(100vw - 48px))` の正方形の拡大押印エリアを置く
- 拡大押印エリアの四隅には既存のCropMarksを使い、紙の押印位置であることを示す
- QRは拡大押印エリアの中央へ置き、**75×75 CSSピクセル**、誤り訂正レベルM、白い余白12pxを変更しない
- QRの近くにSpeechBubble「ここ!」を置く。ただし、QRと白い余白へ重ねない
- スポット名、スポット番号、特定のスタンプ画像は表示しない
- 既存の明るさ、押し当て方、完了確認の3手順は、紙面下部に続く内容として残す
- 「スタンプ帳にもどる」ボタンはQRから96px以上離し、画面下のセーフエリアを確保する

### 6-3. 動きと操作

- 拡大と縮小には `--duration-popup` を使い、位置・大きさ・角丸を連続的に変化させる
- 拡大開始後は、遷移が終わるまで元の押印欄を再度操作できないようにする
- QR表示中は従来どおり共通ヘッダーとタブを隠し、誤操作による画面移動を防ぐ
- ブラウザの戻る操作と「スタンプ帳にもどる」の両方で見開きへ戻れるようにする
- 見開きへ戻ったときは、開く起点になった未押印欄へフォーカスを戻す。押印済みになった場合は見開き全体の見出しへフォーカスを移す
- `prefers-reduced-motion: reduce` では拡大・縮小を行わず、紙面状態を即座に切り替える
- アニメーションが利用できないブラウザでも、拡大後と同じ紙面レイアウトを表示する

## 7. 関連文言の修正

4-3「遊び方」の手順1を変更する。

- 変更前: 「スタンプ帳の紫の番号をタップしてQRを出す」
- 変更後: 「スタンプ帳の空いている押印欄をタップしてQRを出す」

英語も同様に、番号ではなく空いている押印欄をタップする説明へ変更する。

スタンプ帳の補足文は「紫の番号」を操作対象として案内せず、「空いている押印欄」を操作対象として案内する。

## 8. レスポンシブとアクセシビリティ

- 基準画面は幅360〜430pxとし、幅320pxでも横スクロールや表示の見切れが起きないようにする
- 360px幅でも見開きは左右2ページのまま維持し、上下に分割しない
- 見開きの左右余白は、影と背面の紙を含めて最低12pxを確保する
- GOALしおり、押印欄の押下時の移動を含む全状態で、`document.documentElement.scrollWidth` がビューポート幅を超えないようにする
- 横幅が狭い場合は、外側の余白、紙の重なり量、ページ内余白の順に小さくする。押印欄は72×72px未満へ縮小しない
- 高さが不足する端末では縦スクロールを許可し、見開き自体を画面上下で切り取らない
- 押印欄の文字が収まらない場合は文字を12px未満へ縮小せず、2行までの折り返しを許す
- 英語表示でも5つの押印欄の大きさを変えない
- 装飾用の紙の重なりと綴じ目は読み上げ対象から外す
- 未押印欄だけをフォーカス可能にし、押印済み欄は状態を読み上げられるようにする
- 色だけで未押印・押印済み・完走を区別せず、文言と画像を併用する
- `prefers-reduced-motion: reduce` では既存どおり押下と押印演出の動きを止める

## 9. 確認項目の追加

`/dev/gallery` とスクリーンショットで次を確認する。

- 押印0個: 5つすべてが空欄で、左2枠・右3枠の構成が一目で分かる
- 押印2個: 押印済みスタンプと未押印ボタンの違いが、色に依存せず分かる
- 押印5個: 5つのスタンプが見開き内に収まり、GOALしおりが完走状態になる
- 320px、360px、390px、430pxの各幅で、右ページの3枠が重ならず、横スクロールと見切れが発生しない
- 影、背面の紙、GOALしおりまで含め、すべての装飾が画面内へ収まる
- スタンプ帳画面に「スタンプラリー」／「STAMP RALLY」の見出しと、「0/5」形式の進捗カウンターが表示されない
- 日本語と英語の両方で、見出し、案内文、押印欄がはみ出さない
- キーボード操作で未押印欄だけを順に選択でき、フォーカスリングが見える
- 円形の道、地面、木の装飾がスタンプ帳画面に残っていない
- 5つの各押印欄からQR表示を開き、タップ位置から紙面が拡大して見える
- QR表示にスポット名とスポット番号が出ず、どの押印欄から開いてもQRの値と表示寸法が同じである
- QR表示から戻ると見開きへ縮小し、適切な位置へフォーカスが戻る
- `prefers-reduced-motion: reduce` では拡大・縮小せず、操作とQR表示に欠落がない

既存のスクリーンショット対象「スタンプ帳（押印0・2・5個）」は維持し、すべて見開き型で撮影し直す。
